Finish the Playwright API and every official test that applies to a language binding (Chromium first, then Firefox/WebKit). Skip only Node-only harness internals (listener MaxListeners warnings, `__testHookAfterPointerAction`, expect/call-log collapse) until we have an equivalent.

## Browsers and harness

- Firefox and WebKit (suite is Chromium-only).
- HTTPS test server (`httpsServer`, ignoreHTTPSErrors, client certificates). Blocks official SSL `page.goto` cases and autowaiting “links which do not commit navigation”.
- `waitForURL` / `route` globs are not resolved against context `baseURL`.
- URL matches: regex (`UrlMatchRegex`) and predicate (`UrlMatchPredicate`) are supported for routes and waits (`UrlMatch`, see QUESTIONS.md for the engine and escape limits). Glob remains the default. Still open: `URLPattern`, and regex-specific cases that depend on lookaround.
- IndexedDB and WebAuthn credentials on `StorageState`.
- `unrouteAll` `wait` / `ignoreErrors`.
- Tracing, HAR, video, screencast, WebSocket routing. Global `APIRequest.newContext` / `global-fetch` covers the HTTP cases (methods, dispose, userAgent, timeout, extra headers, credentials, empty body, abort, redirects, JSON bodies, maxRedirects, failOnStatusCode). `global-fetch-cookie` covers path filtering, localhost secure cookies, expiry/max-age, Set-Cookie overrides, and storageState round-trip (not IndexedDB or file path). Still open: HTTPS/`ignoreHTTPSErrors`/`securityDetails`, DNS `__testHookLookup` (custom cookie domains), brotli Range, connectOverCDP, bool/numeric params, `close` reason on fetch errors, JS `inspect`/`toJSON()` client serialization. `response.serverAddr` is wrapped but Playwright 1.61.1 omits it when Node happy-eyeballs has not set `remoteAddress` yet. `browsercontext-fetch-algorithms` covers gzip/deflate/br decompression including missing Content-Length, chunked, and empty bodies.
